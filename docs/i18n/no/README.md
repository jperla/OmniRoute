## ~ 1.62B tokens / måned på tvers av tredjeparts gratis nivåer

> **Ta med egne leverandørkontoer.** Dette er en estimert sum på tvers av separat kvalifiserte tredjeparts gratisnivåer, ikke et symbolsk tilskudd fra OmniRoute. Registrer deg, innhent legitimasjon der det er nødvendig, og koble til leverandørene du kan bruke; hver leverandør kontrollerer sine grenser, tilgjengelighet og vilkår.
>
> Å stable gratis nivåer for hånd er smertefullt — dusinvis av SDKs, dusinvis av rategrenser, og ingen anelse om hvor mye du faktisk har. OmniRoute kataloger** 465 frittstående oppføringer fordelt på 34 gjentakende bassengnøkler** og beregner token-overskriften fra** 17 bassenger med et publisert positivt månedlig budsjett pluss fem Groq tak per modell** , deduplisert av delt basseng. Kvoter som bare åpnes etter en regional identitetssjekk (i dag: ModelScope) vises fra hverandre, +~ 6M bak regional identitetsverifisering, og blir aldri summert inn i overskriften. Resultatet forblir synlig på dashbordet (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute free-tier budget card: ~1.62B free tokens per month steady, up to ~2.22B in the first month with signup credits, from 34 documented recurring pool keys covering 465 cataloged free-tier entries behind one endpoint. Honest pool-deduped math — each shared pool counted once, including 17 recurring pools with a published positive monthly token budget plus five per-model Groq caps; 12 providers are marked avoid in the terms-risk catalog so you decide. Budget bar includes Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (five per-model caps) and smaller pools, plus first-month signup credits and permanently-free no-token-cap providers surfaced separately so they never inflate the headline. Live used/remaining on /dashboard/free-tiers."/>

> Animert sammendrag av live `/dashboard/free-tiers` -siden. Full metodikk (pool dedupe, kredittnivåer, leverandørvilkår):** [docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)** .
>
> <sub> Disse tallene revideres annenhver uke mot livekatalogen og** flytte begge veier** — en leverandør avslutter et gratis nivå og antallet synker; en ny lander og den klatrer. Vi publiserer hva katalogen faktisk beregner, aldri en avrundet best case.</sub>

## Installer, koble til en leverandør, og rute deretter gjennom ett endepunkt

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` trenger en kvalifisert rute. En ny installasjon kan ikke ha noen kvalifiserte nøkkelfrie mål, og en nøkkelfri leverandør kan avvise tredjepartsklienter. Leverandører merket `tos: avoid`, inkludert Kiro, er ekskludert fra automatisk ruting som standard; å koble til en konto overstyrer ikke denne innstillingen. Se [Free Tiers Guide](docs/getting-started/FREE-TIERS-GUIDE.md) før du velger leverandør.</sub>

## Combos: flaggskipet

1. **Start med `auto`.** Still inn modellen i din OpenAI-kompatible klient. OmniRoute bygger en virtuell kombinasjon fra tilkoblede leverandører og scorer kandidater live.
2. **Lagre en kombinasjon for mer kontroll.** Velg et navn, målliste og strategi, og bruk deretter det navnet som modell. Strategien setter hvilket mål som går først og hvordan resten prøves.

En kombinasjon ruter automatisk på tvers av modellene. Ved oppbrukt kvote, leverandørsvikt eller modellsperring prøver den det neste kvalifiserte, sunne målet.

### Zero-config: bare bruk `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Varianter justerer vektene. Sist kjente-god ruting forblir hos den siste vellykkede leverandøren til den mislykkes, og scorer deretter på nytt. `auto/fast` og `auto/cheap` uttrykker preferanser uten å garantere den raskeste eller billigste modellen.

| Modell ID           | Oppførsel                                                                                                                                                                                                                                                                         |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Balanserte standardvekter.                                                                                                                                                                                                                                                        |
| `auto/fast`         | Foretrekker lav latenstid og leverandørhelse.                                                                                                                                                                                                                                     |
| `auto/cheap`        | Foretrekker lavere katalogpriser.                                                                                                                                                                                                                                                 |
| `auto/coding`       | Kvalitets-første vekter for kodegenerering.                                                                                                                                                                                                                                       |
| `auto/smart`        | Kvalitet først vekter med 10 % leting (standard 5 %).                                                                                                                                                                                                                             |
| `auto/lkgp`         | Eksplisitt sist kjente gode ruting med samme vekter som `auto`.                                                                                                                                                                                                                   |
| `auto/subscription` | Bruker kun bekreftet plankvote. Returnerer HTTP 503 når ingen er tilgjengelig og unngår fakturert reserve.                                                                                                                                                                        |
| `auto/thrifty`      | Plan → nøkkelløs → gratis → billig → premium. Kan nå fakturerte modeller og returnere til planen når kvote og nedkjøling tillater det.                                                                                                                                            |
| `auto/offline`      | Foretrekker takhøyde for kvoter og takstgrenser. Forespørsler sendes fortsatt til leverandørene dine.                                                                                                                                                                             |
| `auto/chaos`        | Én modell per leverandør parallelt, opptil fem som standard eller ti når konfigurert. En oppstrøms samtale per modell. Returnerer det topprangerte svaret eller det siste vellykkede panelsvaret hvis toppmodellen mislykkes. Bruk `fusion` til å syntetisere svar med en dommer. |

Eksempler på kategorier og valgfrie lag inkluderer `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` og `auto/vision`. Hvis ingen tilkoblede kandidater matcher, returnerer forespørselen HTTP 503 og utvalget forblir smalt. [Auto-kombinasjonsguide](./docs/routing/AUTO-COMBO.md) · [Abonnement-første ruting](./docs/routing/SUBSCRIPTION_LADDER.md)

### Eller bygg din egen: 22 rutingstrategier

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

CLI aksepterer 15 av 22 strategier. Dashbordet og kombinasjonene API godtar alle 22.

| Strategi            | Oppførsel                                                                                                                                                                                                                         |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Rangeringskandidater lever med 16-faktor Auto-Combo-scoreren.                                                                                                                                                                     |
| `cache-optimized`   | Foretrekk kontoen som sannsynligvis har ledetekstprefikset i hurtigbufferen.                                                                                                                                                      |
| `context-optimized` | Prøv det største kjente kontekstvinduet først.                                                                                                                                                                                    |
| `context-relay`     | Behold bestillingen og send et samtalesammendrag når du bytter konto.                                                                                                                                                             |
| `cost-optimized`    | Sorter etter kataloginndata-token-pris, ukjent sist. Den endelige forespørselskostnaden kan variere.                                                                                                                              |
| `expiry-first`      | Bruk kvoten som sannsynligvis utløper, høyeste rest per time til tilbakestillingen først.                                                                                                                                         |
| `fill-first`        | Hold deg på det første tilgjengelige målet til det går tom eller mislykkes, og gå deretter videre.                                                                                                                                |
| `fusion`            | Spør et panel parallelt og la en dommer syntetisere ett svar.                                                                                                                                                                     |
| `headroom`          | Velg den mest ledige kapasiteten i 5-timers og ukesvinduer.                                                                                                                                                                       |
| `jev`               | TypeSafe Jev velger hvilke oppføringer i den rangerte listen din som kjøres. Slå på `COMBO_JEV_STRATEGY_ENABLED` for å sende et utdrag per forespørsel og bruke betalte TypeSafe -anrop. Når den er av, gjelder bestillingen din. |
| `least-used`        | Velg målet med færrest registrerte forespørsler i denne kombinasjonen.                                                                                                                                                            |
| `lkgp`              | Prøv den siste vellykkede leverandøren først, ellers behold bestillingen din.                                                                                                                                                     |
| `p2c`               | Prøv to mål og velg etter suksessrate og ventetid.                                                                                                                                                                                |
| `pipeline`          | Mat hvert trinns utdata inn i neste mål i rekkefølge og returner bare det endelige svaret.                                                                                                                                        |
| `priority`          | Prøv mål i bestillingen din. Session stickiness bevarer den.                                                                                                                                                                      |
| `quota-weighted`    | Hopp over oppbrukte kontoer og trekk etter restkvote og last under fly.                                                                                                                                                           |
| `random`            | Bland for hver forespørsel. Det samme første målet kan gjentas.                                                                                                                                                                   |
| `reset-aware`       | Poeng gjenværende kvote og tid for å tilbakestille på tvers av økt- og ukevinduer.                                                                                                                                                |
| `reset-window`      | Prøv kontoen hvis kvotevindu tilbakestilles snarest.                                                                                                                                                                              |
| `round-robin`       | Roter i rekkefølge, tre suksesser per mål som standard.                                                                                                                                                                           |
| `strict-random`     | Handle fra en stokket kortstokk slik at hvert mål leder én gang før repetisjoner.                                                                                                                                                 |
| `weighted`          | Tegn et første mål etter vekt og behold resten som fallbacks. Delingen er statistisk. Bruk `round-robin` for streng rotasjon.                                                                                                     |

Kvotestrategier bruker live data der leverandører rapporterer det, inkludert 5-timers og ukentlige abonnementsvinduer. `fusion` og `pipeline` foretar flere oppstrømsanrop per forespørsel.

16-faktorscoreren bruker kvote, helse, kostnad, latens, oppgavetilpasning, stabilitet, nivåprioritet, nivåtilhørighet, spesifisitetsmatch, kontekstilhørighet, hurtigbuffertilknytning, økttilgjengelighet, tilbakestillingsvinduaffinitet, tilkoblingstetthet, kvalitet og pålitelighet. Vektene varierer etter profil. Buffertilhørighet, tilbakestillingsvinduaffinitet og pålitelighet har null vekt som standard. [Poengfaktorer](./docs/routing/AUTO-COMBO.md#how-it-works-persisted-auto-combos)

### Spenst er bygget i: 3 uavhengige lag

Feil håndteres i tre omfang, så én dårlig modell tar ikke ned kontoen sin, og én dårlig konto tar ikke ned leverandøren.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Hvis en hel leverandør er nede

De** leverandør effektbryter** åpnes etter 8 (OAuth) eller 12 (API key) feil med status 408, 500, 502, 503 eller 504. Kombinasjoner hopper over den leverandøren mens den er åpen. Etter 60 s eller 30 s avgjør én sondeforespørsel om den lukkes.

#### Hvis én nøkkel eller konto er satsbegrenset

De** tilkoblingsavkjøling** benker bare den forbindelsen, med eksponentiell backoff fra 5 s (OAuth) eller 3 s (API tast). Andre nøkler for samme leverandør fortsetter å tjene.

#### Hvis en modell blir avvist

De** modell lockout** blokkerer bare den modellen på den forbindelsen etter en per-modell 429, 404 eller tilgangsnektelse. Andre modeller på samme tilkobling fortsetter å tjene.

Forbudte, utløpte og kredittløse tilkoblinger er terminaltilstander, ikke nedkjøling: de venter på at du skal fikse dem.

## Full CLI, MCP og A2A

> OmniRoute sender en kommandolinjeklient med** 91 kommandoer og kommandogrupper på toppnivå** (754 kommandoer som teller underkommandoer), en**MCP server med 110 verktøy og 33 scopes** , og en**A2A agent med 6 ferdigheter** . Skript, terminaler og AI agenter kan alle operere den samme gatewayen.

### En ekte CLI, ikke bare `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

Det globale `--output table|json|jsonl|csv` flagget gjør de samme kommandoene brukbare fra skript og CI.

### Ekstern modus: CLI på den bærbare datamaskinen, OmniRoute på en server

Logg inn én gang på en ekstern server. CLI lagrer den som en** kontekst** , og senere kommandoer kjøres mot den serveren til du bytter tilbake.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Token-omfang | <img width="2000" height="0" alt=""> Hva det tillater              |
| ------------ | ------------------------------------------------------------------ |
| `read`       | Liste og inspisere: modeller, status, logger, bruk                 |
| `write`      | `read` plus konfigurere og bruke: klientoppsett, nøkler, konfig    |
| `admin`      | `write` plus administrere: tokens, leverandører, tjenester, policy |

En bar vert får `http://` og port 20128; sende en full `https://` URL når serveren sitter bak TLS. Ruter som kan skape prosesser forblir bare loopback, uansett token.

### Koble til en agent

En agent, eller din egen kode, kan drive ruting, leverandører, kombinasjoner, cache, komprimering og minne gjennom alle disse grensesnittene. HTTP -baner betjenes av gatewayen, som standard på `http://localhost:20128`.

| Grensesnitt              | Endepunkt eller kommando   | Bruk den til                                                                            |
| ------------------------ | -------------------------- | --------------------------------------------------------------------------------------- |
| MCP over stdio           | `omniroute --mcp`          | Claude Desktop, Cursor og andre lokale MCP klienter                                     |
| MCP over Streamable HTTP | `/api/mcp/stream`          | Eksterne MCP klienter: 110 verktøy, 33 omfang, hver samtale skrevet til revisjonsloggen |
| MCP over SSE             | `/api/mcp/sse`             | Kunder som fortsatt bruker SSE -transporten                                             |
| A2A oppdagelse           | `/.well-known/agent.json`  | Agentkort: forteller andre agenter hva OmniRoute kan gjøre                              |
| A2A utførelse            | `POST /a2a`                | JSON-RPC 2.0-oppgaver, synkrone eller streamet over SSE, på tvers av 6 ferdigheter      |
| REST API                 | `/v1/*`                    | OpenAI-kompatibel chat, svar, innebygging, bilder, lyd og OCR                           |
| Webhooks                 | `/api/webhooks`            | Hendelser til Slack, Discord, Telegram eller hvilken som helst URL med HMAC -signering  |
| Fjernkontroll CLI        | `omniroute connect <host>` | Kjør en ekstern forekomst med scoped tilgangstokener                                    |

De seks A2A ferdighetene er `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` og `list-capabilities`.

**Før du kobler til:**

- **MCP over HTTP starter deaktivert.** Slå den på med `omniroute mcp enable --transport streamable-http` eller fra dashbordets Endpoints-side. Én HTTP -transport er aktiv om gangen: `streamable-http` tjener `/api/mcp/stream`, `sse` tjener `/api/mcp/sse`.
- **A2A starter deaktivert.** Aktiver det på dashbordets endepunkter-side. `POST /a2a` følger da de samme API-nøkkelreglene som `/v1`.
- **Remote MCP trenger en passende nøkkel.** `/api/mcp/*` svarer bare loopback som standard. Fra en annen vert, send en nøkkel med `manage` eller `admin` (alle verktøy), eller med `mcp:connect` pluss omfanget av verktøyene du trenger. For nøkler uten `manage`/`admin` håndheves alltid verktøyomfang.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Spar 15–95 % tokens — automatisk

### Hvordan det fungerer — pipeline, architecture & savings math

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

Standard stablet kombinasjon kjører `RTK → Caveman`. Når begge virker på samme tool/context nyttelast, spares sammensatt:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Kodeblokker, URLs, JSON og strukturerte data er** alltid beskyttet** av konserveringsmotoren.

> **Hvorfor bruke mange tokens når få tokens gjør susen?** Hver forespørsel går gjennom OmniRoute kompresjonspipeline** gjennomsiktig** — ingen klientendringer. Det er nå en** stabel med 12 komponerbare motorer** som kjører i rekkefølge og miks og matcher per rutekombinasjon — som bygger på ideer fra [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) og [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

| ------------------------------ | ----------------------------------------------------------------------------------- |

#### Adaptivt kontekstbudsjett

| Innstilling | Alternativer                                                                                                                                                                      |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Politikk    | `reserve-output` (standard) setter av plass til svaret og en sikkerhetsmargin. `percentage` bruker en del av kontekstvinduet. `absolute` setter et fast token-mål.                |
| Modus       | `floor` kan eskalere den valgte planen for å passe kontekstvinduet. `replace-autotrigger` bruker budsjettet for automatisk eskalering. `off` beholder token-terskel auto-trigger. |

## Flere installasjonsmetoder — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` følger den høyeste** publisert** stabil SemVer. Den sporer ikke git `main`. Pin `:X.Y.Z` for GitOps. Se [Docker utgivelseskanaler](docs/guides/DOCKER_GUIDE.md#release-channels).Bildetålene**`OMNIROUTE_MEMORY_MB=1024`** . Det er nok til dashbordet og en lett prat.** Kodemidler** (`POST /v1/responses` fra Claude Code, Codex, Grok, …) trenger en mye større V8-haug eller prosessen `FATAL ERROR` s ved ~ 12 GiB under to overlappende lange kontekster. Størrelse på beholderen over haugen (native buffere sitter utenfor V8):

| <img width="2000" height="0" alt=""> Arbeidsmengde | Heap (`-e OMNIROUTE_MEMORY_MB`) | Beholder (`--memory`) |
| -------------------------------------------------- | ------------------------------- | --------------------- |
| Dashboard / lett chat                              | `1024` (bildestandard)          | ≥ 2 g                 |
| En kodeagent                                       | `8192`                          | ≥ 10 g                |
| To samtidige lange `/v1/responses`                 | `10240`–`12288`                 | ≥ 12–16 g             |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Full tabell: [Docker Guide — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Forhåndsutgivelse av Docker kanal:** `diegosouzapw/omniroute:next` og `diegosouzapw/omniroute:next-web` følger gjeldende standard `release/v*` gren. Disse mutable taggene er kun ment for å teste uutgitte rettelser og er** ikke støttet for produksjon** . Se [Docker utgivelseskanaler](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Standard `bun install` og global installasjon (`bun install -g omniroute`) støttes via Bun kjøretidsdeteksjon:

- **Innebygd `bun:sqlite`** : OmniRoute bruker Bun innebygde `bun:sqlite` driver når du kjører under Bun, og faller tilbake til `better-sqlite3` på Node.js eller `sql.js`.
- **Automatisk Webpack-buntervalg i dev** : Utvikling (`bun run dev`) oppdager automatisk Bun og deaktiverer Turbopack til fordel for Webpack for å forhindre innfødt V8-bindingsinkompatibilitet. Produksjonsbygg (`bun run build`) følger `OMNIROUTE_USE_TURBOPACK` nøyaktig som på Node: Turbopack som standard, `OMNIROUTE_USE_TURBOPACK=0` for å bygge med Webpack (`Dockerfile.bun` eksponerer det som en `--build-arg`).
- **Dedikert Bun Dockerfile** : Flertrinns `Dockerfile.bun` for native Bun -produksjonsdistribusjoner (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Raskere / slankere installasjon (hopp over den opprinnelige versjonen)**

Den opprinnelige SQLite motoren (`better-sqlite3`) er en** valgfri** avhengighet, så en global installasjon blokkerer aldri kompilering fra kilden: den bruker en forhåndsbygd binær når en matcher platform/Node din, og faller ellers transparent tilbake til en ren JS-motor (`node:sqlite` på Node 22 +, ellers den medfølgende `sql.js` WASM) — ingen byggeverktøy kreves.

For å hoppe over etterinstallasjonen** innfødt oppvarming** helt (CI, hodeløse eller trege maskiner). Merk: dette hopper bare over det opprinnelige SQLite -oppvarmingstrinnet (`scripts/postinstall.mjs`); binary-copy/repair kroken (`scripts/build/postinstall.mjs`) kjører fortsatt normalt:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

For de raskeste installasjonene foretrekker** pnpm** (innholdsadressert butikk + harde lenker — se ovenfor). For en dashbordfri, hodeløs kjøretid, bruk Docker `base` profilen (over) eller [Termux-guiden](docs/guides/TERMUX_GUIDE.md). CLI og web-dashbordet betjenes av samme prosess på én port, så det er ingen separat CLI-only-pakke i dag.

### Hvordan bidra

1. Fordel depotet
2. Filial fra** aktiv** `release/vX.Y.Z` tip (ikke `main`) — se [Forgrenings- og frigjøringsmodell](docs/ops/BRANCHING_MODEL.md)
3. Lag din funksjonsgren (`git checkout -b feat/amazing-feature`)
4. Bekreft endringene dine (`git commit -m 'feat: add amazing feature'`)
5. Skyv til grenen (`git push origin feat/amazing-feature`)
6. Åpne en Pull-forespørsel med** base = den `release/vX.Y.Z` grenen**

Se [CONTRIBUTING.md](CONTRIBUTING.md) for detaljerte retningslinjer.

## Anerkjennelser

OmniRoute står på skuldrene til kjemper. Det startet som en gaffel av** [9 ruteren](https://github.com/decolua/9router)** og en TypeScript port av Go-prosjektet** [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)** — og derfra ble hvert delsystem nedenfor inspirert av et åpen kildekode-prosjekt som kom dit først. Hver av dem formet en betongbit av OmniRoute. Dette er vår takk til dem alle. 🙏

> Antall ⭐ stjerner bekreftet fra GitHub sin REST API 16. november 2026 — go gi disse prosjektene en stjerne. Antall er et eksakt datert øyeblikksbilde og vil naturligvis endres. GrokBridge returnerte HTTP 404 på den datoen; dens attribusjon beholdes.
