## ~ 1,62B tokenů / měsíc napříč úrovněmi zdarma třetích stran

> **Přineste si vlastní účty poskytovatelů.** Jedná se o odhadovaný souhrn napříč samostatně způsobilými bezplatnými úrovněmi třetích stran, nikoli o tokenový grant od OmniRoute. Zaregistrujte se, v případě potřeby získejte přihlašovací údaje a připojte poskytovatele, které můžete použít; každý poskytovatel kontroluje své limity, dostupnost a podmínky.
>
> Ruční skládání bezplatných úrovní je bolestivé — desítky SDKs, desítky limitů sazeb a netušíte, kolik ve skutečnosti máte. OmniRoute katalogy** 465 volných položek přes 34 opakujících se klíčů fondu** a vypočítá titulek tokenu z** 17 fondů se zveřejněným kladným měsíčním rozpočtem plus pět stropů Groq na model** , deduplikované sdíleným fondem. Kvóty, které se otevřou až po kontrole regionální identity (dnes: ModelScope), jsou zobrazeny odděleně, +~ 6M za ověřením regionální identity, a nikdy nejsou sečteny do titulku. Výsledek zůstane viditelný na řídicím panelu (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute free-tier budget card: ~1.62B free tokens per month steady, up to ~2.22B in the first month with signup credits, from 34 documented recurring pool keys covering 465 cataloged free-tier entries behind one endpoint. Honest pool-deduped math — each shared pool counted once, including 17 recurring pools with a published positive monthly token budget plus five per-model Groq caps; 12 providers are marked avoid in the terms-risk catalog so you decide. Budget bar includes Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (five per-model caps) and smaller pools, plus first-month signup credits and permanently-free no-token-cap providers surfaced separately so they never inflate the headline. Live used/remaining on /dashboard/free-tiers."/>

> Animované shrnutí živé stránky `/dashboard/free-tiers`. Úplná metodika (odstranění duplicitního fondu, úrovně kreditu, podmínky poskytovatele):** [docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)** .
>

## Nainstalujte, připojte poskytovatele a poté směrujte přes jeden koncový bod

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` potřebuje vhodnou trasu. Nová instalace nemůže mít žádné způsobilé bezklíčové cíle a poskytovatel bezklíčového připojení může odmítnout klienty třetích stran. ## Kombinace: vlajková loď

1. **Začněte s `auto`.** Nastavte model ve svém klientovi kompatibilním s OpenAI. OmniRoute vytváří virtuální kombo z připojených poskytovatelů a živě boduje kandidáty.
2. **Uložte si kombinaci pro větší kontrolu.** Vyberte název, cílový seznam a strategii a poté toto jméno použijte jako model. Strategie určuje, který cíl jde jako první a jak se zkouší zbytek.

Kombinace vede mezi modely automaticky. Při vyčerpání kvóty, selhání poskytovatele nebo uzamčení modelu se pokusí o další vhodný, zdravý cíl.

### Zero-config: stačí použít `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Varianty ladí váhy. Směrování podle posledního známého dobrého zůstává u posledního úspěšného poskytovatele, dokud se nezdaří, a poté znovu vyhodnotí. `auto/fast` a `auto/cheap` vyjadřují preference bez záruky nejrychlejšího nebo nejlevnějšího modelu.

| Model ID            | Chování                                                                                                                                                                                                                                                                              |
| :------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Vyvážené výchozí váhy.                                                                                                                                                                                                                                                               |
| `auto/fast`         | Upřednostňuje nízkou latenci a zdraví poskytovatele.                                                                                                                                                                                                                                 |
| `auto/cheap`        | Upřednostňuje nižší katalogové ceny.                                                                                                                                                                                                                                                 |
| `auto/coding`       | Závaží kvality pro generování kódu.                                                                                                                                                                                                                                                  |
| `auto/smart`        | Váhy na prvním místě s 10% průzkumem (výchozí 5%).                                                                                                                                                                                                                                   |
| `auto/lkgp`         | Explicitní směrování posledního známého dobrého se stejnými váhami jako `auto`.                                                                                                                                                                                                      |
| `auto/subscription` | Používá pouze živě ověřenou kvótu plánu. Vrátí HTTP 503, když žádná není k dispozici, a zabrání fakturovanému nouzovému řešení.                                                                                                                                                      |
| `auto/thrifty`      | Plán → keyless → zdarma → levný → premium. Může dosáhnout účtovaných modelů a vrátí se k plánu, když to kvóta a cooldown dovolí.                                                                                                                                                     |
| `auto/offline`      | Upřednostňuje prostor pro kvóty a limity sazeb. Požadavky stále chodí vašim poskytovatelům.                                                                                                                                                                                          |
| `auto/chaos`        | Jeden model na poskytovatele paralelně, až pět ve výchozím nastavení nebo deset při konfiguraci. Jedno upstream volání na model. Pokud top model selže, vrátí odpověď s nejvyšším hodnocením nebo poslední úspěšnou odpověď panelu. Použijte `fusion` k syntéze odpovědí se soudcem. |

Příklady kategorií a volitelných úrovní zahrnují `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` a `auto/vision`. Pokud neodpovídá žádný připojený kandidát, požadavek vrátí HTTP 503 a fond zůstane úzký. [Průvodce automatickým kombinováním](./docs/routing/AUTO-COMBO.md) · [Směrování podle předplatného](./docs/routing/SUBSCRIPTION_LADDER.md)

### Nebo si vytvořte vlastní: 22 směrovacích strategií

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

CLI přijímá 15 z 22 strategií. Přístrojová deska a komba API akceptují všech 22.

| Strategie           | Chování                                                                                                                                                                                                                               |

### Odolnost je vestavěna: 3 nezávislé vrstvy

Poruchy jsou řešeny ve třech rozsahech, takže jeden špatný model nesundá svůj účet a jeden špatný účet nesundá svého poskytovatele.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Pokud dojde k výpadku celého poskytovatele

The** jistič poskytovatele** otevře se po 8 (OAuth) nebo 12 (klíč API ) selhání se stavem 408, 500, 502, 503 nebo 504. Kombinace přeskakují tohoto poskytovatele, když je otevřený. Po 60 s nebo 30 s jeden požadavek sondy rozhodne, zda se zavře.

#### Pokud je jeden klíč nebo účet omezen sazbou

The** ochlazení připojení** lavičky pouze toto spojení, s exponenciálním stažením od 5 s (OAuth) nebo 3 s ( klávesa API ). Ostatní klíče od stejného poskytovatele se nadále zobrazují.

#### Pokud je jeden model odmítnut

The** uzamčení modelu** blokuje pouze tento model na tomto připojení po odepření přístupu pro každý model 429, 404. Ostatní modely na stejném připojení nadále slouží.

Zakázaná, prošlá připojení a připojení bez kreditu jsou terminálové stavy, nikoli cooldowny: čekají, až je opravíte.

## Úplné CLI, MCP a A2A

> OmniRoute dodává klienta příkazového řádku s** 91 příkazů nejvyšší úrovně a skupin příkazů** (754 příkazů počítání dílčích příkazů), an**MCP server se 110 nástroji a 33 rozsahy** a**A2A agent se 6 dovednostmi** . Skripty, terminály a agenti AI mohou ovládat stejnou bránu.

### Skutečná CLI, nejen `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

Globální příznak `--output table|json|jsonl|csv` umožňuje použití stejných příkazů ze skriptů a CI.

### Vzdálený režim: CLI na vašem notebooku, OmniRoute na serveru

Přihlaste se jednou ke vzdálenému serveru. CLI jej uloží jako a** kontext** a pozdější příkazy běží proti tomuto serveru, dokud nepřepnete zpět.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Rozsah tokenu | <img width="2000" height="0" alt=""> Co umožňuje                         |
| ------------- | ------------------------------------------------------------------------ |
| `read`        | Seznam a kontrola: modely, stav, protokoly, použití                      |
| `write`       | `read` plus konfigurace a použití: nastavení klienta, klíče, konfigurace |
| `admin`       | `write` plus spravovat: tokeny, poskytovatele, služby, zásady            |

### Připojte agenta

Agent nebo váš vlastní kód může řídit směrování, poskytovatele, komba, mezipaměť, kompresi a paměť prostřednictvím kteréhokoli z těchto rozhraní. Cesty HTTP jsou obsluhovány bránou, ve výchozím nastavení `http://localhost:20128`.

| Rozhraní                     | Koncový bod nebo příkaz    | Použijte to pro                                                                           |
| ---------------------------- | -------------------------- | ----------------------------------------------------------------------------------------- |
| MCP přes stdio               | `omniroute --mcp`          | Claude Desktop, Cursor a další místní MCP klienti                                         |
| MCP přes streamovatelné HTTP | `/api/mcp/stream`          | Vzdálení klienti MCP : 110 nástrojů, 33 rozsahů, každé volání zapsáno do protokolu auditu |
| MCP přes SSE                 | `/api/mcp/sse`             | Klienti, kteří stále využívají dopravu SSE                                                |
| A2A objev                    | `/.well-known/agent.json`  | Karta agenta: říká ostatním agentům, co OmniRoute může dělat                              |
| exekuce A2A                  | `POST /a2a`                | Úlohy JSON-RPC 2.0, synchronní nebo streamované přes SSE, v 6 dovednostech                |
| REST API                     | `/v1/*`                    | Chat kompatibilní s OpenAI, odpovědi, vkládání, obrázky, zvuk a OCR                       |
| Webhooky                     | `/api/webhooks`            | Události do Slack, Discord, Telegram nebo jakéhokoli URL s podpisem HMAC                  |
| Vzdálená CLI                 | `omniroute connect <host>` | Řiďte vzdálenou instanci pomocí tokenů pro omezený přístup                                |

Šest dovedností A2A je `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` a `list-capabilities`.

**Než se připojíte:**

- **spouštění MCP přes HTTP je zakázáno.** Zapněte jej pomocí `omniroute mcp enable --transport streamable-http` nebo ze stránky Koncové body řídicího panelu. Aktivní je vždy jeden přenos HTTP : `streamable-http` slouží `/api/mcp/stream`, `sse` slouží `/api/mcp/sse`.
- **A2A se spustí zakázáno.** Povolte jej na stránce Koncové body řídicího panelu. `POST /a2a` se pak řídí stejnými pravidly pro klíč API jako `/v1`.
- **Remote MCP potřebuje vhodný klíč.** `/api/mcp/*` standardně odpovídá pouze zpětné smyčce. Z jiného hostitele odešlete klíč s `manage` nebo `admin` (všechny nástroje) nebo s `mcp:connect` plus rozsahy nástrojů, které potřebujete. Pro klíče bez `manage`/`admin` jsou rozsahy nástrojů vždy vynuceny.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

### Jak to funguje — potrubí, architektura a úspory matematiky

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

Výchozí skládané kombo spouští `RTK → Caveman`. Když oba působí na stejné užitečné zatížení tool/context, úsporná směs:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Bloky kódu, URLs, JSON a strukturovaná data jsou** vždy chráněna** konzervačním motorem.

> **Proč používat mnoho žetonů, když málo žetonů stačí?** Každý požadavek prochází kompresním potrubím OmniRoute** transparentně** — žádné změny klienta. Nyní je to a** hromada 12 skládacích motorů** které běží v pořádku a mix & match podle směrovacího komba — na základě nápadů od [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) a [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

## Více instalačních metod — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` následuje nejvyšší** zveřejněno** stabilní SemVer. Nesleduje git `main`. Pin `:X.Y.Z` pro GitOps. Viz [Docker Release Channels](docs/guides/DOCKER_GUIDE.md#release-channels). Obrazové kolíky**`OMNIROUTE_MEMORY_MB=1024`** . To stačí na palubní desku a lehké popovídání.** Kódovací agenti** (`POST /v1/responses` od Claude Code, Codex, Grok, …) potřebují mnohem větší haldu V8 nebo proces `FATAL ERROR` s při ~ 12 GiB ve dvou překrývajících se dlouhých kontextech. Velikost kontejneru nad hromadou (nativní vyrovnávací paměti jsou umístěny mimo V8):

| <img width="2000" height="0" alt=""> pracovní zátěž | Hromada (`-e OMNIROUTE_MEMORY_MB`) | Kontejner (`--memory`) |
| --------------------------------------------------- | ---------------------------------- | ---------------------- |
| Dashboard / light chat                              | `1024` (výchozí obrázek)           | ≥ 2 g                  |
| Jeden kódovací agent                                | `8192`                             | ≥ 10 g                 |
| Dvě souběžné dlouhé `/v1/responses`                 | `10240`–`12288`                    | ≥ 12–16 g              |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
```

Standardní `bun install` a globální instalace (`bun install -g omniroute`) jsou podporovány prostřednictvím detekce běhového prostředí Bun :

- **Vestavěná `bun:sqlite`** : OmniRoute používá Bun vestavěný ovladač `bun:sqlite`, když běží pod Bun, spadá zpět na `better-sqlite3` na Node.js nebo `sql.js`.
- **Automatický výběr balíku Webpack ve vývoj** : Vývoj (`bun run dev`) automaticky detekuje Bun a deaktivuje Turbopack ve prospěch Webpacku, aby se zabránilo nekompatibilitě nativní vazby V8. Produkční sestavení (`bun run build`) následují `OMNIROUTE_USE_TURBOPACK` přesně jako na Node: Turbopack ve výchozím nastavení, `OMNIROUTE_USE_TURBOPACK=0` pro sestavení s Webpack (`Dockerfile.bun` jej odhaluje jako `--build-arg`).
- **Vyhrazený Bun Dockerfile** : Vícestupňové `Dockerfile.bun` pro nativní produkční nasazení Bun (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Rychlejší / štíhlejší instalace (přeskočte nativní sestavení)**

Nativní SQLite engine (`better-sqlite3`) je an** volitelný** závislost, takže globální instalace nikdy neblokuje kompilaci ze zdroje: používá předkompilovaný binární soubor, když se shoduje s vaším platform/Node, a jinak se transparentně vrací k čistému JS enginu (`node:sqlite` na Node 22 +, jinak přibalený `sql.js` WASM) — nejsou potřeba žádné nástroje pro sestavení.

Chcete-li přeskočit postinstalaci** nativní rozcvička** úplně (CI, bezhlavé nebo pomalé stroje). Poznámka: toto pouze přeskočí nativní krok zahřívání SQLite (`scripts/postinstall.mjs`); binary-copy/repair hook (`scripts/build/postinstall.mjs`) stále běží normálně:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Pro nejrychlejší instalaci preferujte** pnpm** (adresný obchod + pevné odkazy — viz výše). Pro běhové prostředí bez řídicího panelu bez hlavy použijte profil Docker `base` (výše) nebo [průvodce Termux](docs/guides/TERMUX_GUIDE.md). CLI a webový dashboard jsou obsluhovány stejným procesem na jednom portu, takže dnes neexistuje žádný samostatný balíček pouze pro CLI.

### Jak přispět

1. Fork úložiště
2. Pobočka z** aktivní** `release/vX.Y.Z` tip (ne `main`) — viz [model větvení a uvolnění](docs/ops/BRANCHING_MODEL.md)
3. Vytvořte si větev funkcí (`git checkout -b feat/amazing-feature`)
4. Potvrdit změny (`git commit -m 'feat: add amazing feature'`)
5. Push to branch (`git push origin feat/amazing-feature`)
6. Otevřete žádost o stažení pomocí** základna = ta větev `release/vX.Y.Z`**

Viz [CONTRIBUTING.md](CONTRIBUTING.md) pro podrobné pokyny.

### Vydání nové verze

```bash
# Create a release — npm publish happens automatically
VERSION=x.y.z
gh release create "v${VERSION}" --title "v${VERSION}" --generate-notes
```

## Poděkování

OmniRoute stojí na ramenou obrů. Začalo to jako rozchod** [9směrovač](https://github.com/decolua/9router)** a TypeScript port projektu Go** [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)** — a odtud byl každý subsystém níže inspirován projektem s otevřeným zdrojovým kódem, který se tam dostal jako první. Každý z nich vytvaroval konkrétní kus OmniRoute. Tímto jim všem patří naše poděkování. 🙏

> Počty hvězd ⭐ ověřené z GitHubREST API 16. listopadu 2026 — go dát těmto projektům hvězdičku. Počty jsou přesným datem a budou se přirozeně měnit. GrokBridge vrátil HTTP 404 k tomuto datu; jeho přiřazení je zachováno.
